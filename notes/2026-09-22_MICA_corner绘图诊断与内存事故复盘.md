## 1. 本次工作的目标和边界

最初问题来自 Mrk817_a 的 corner 图。即使某些波段保存了约千量级等权后验样本，二维等高线仍表现为大量碎片、小岛和不规则轮廓，不像常见的平滑椭圆。需要回答的不是“怎样把图修饰得漂亮”，而是：

1. 碎片来自真实后验结构、采样不足，还是绘图离散化？
2. 在不删除样本、不改变分位数、不把后验强行高斯化的前提下，怎样画得更稳定？
3. 新画法能否通过项目主入口批量复用？
4. 批量导出时怎样控制内存，并避免中断留下损坏文件？

本次没有重新运行 MICA，没有改变先验、后验、成分排序规则或科学估计量。所有改动均属于读取已有后验后的绘图与导出。

## 2. 初始异常：corner 图“稀碎”不等于后验一定未收敛

### 2.1 Mrk817_a 的实际样本情况

Gaussian/free/2comp 分支各波段保存的等权联合后验样本数及不同联合取值数为：

| 波段 | 等权样本数 | 不同联合取值数 |
|---|---:|---:|
| UVM2 | 365 | 223 |
| UVW1 | 1704 | 1036 |
| U | 2396 | 1409 |
| B | 1670 | 987 |
| V | 2139 | 1318 |

重复样本来自加权样本转为等权样本时的重采样过程。它们携带概率质量，不能为了让图看起来更平滑而去重。不同联合取值数也不是有效独立样本量，不能直接代替收敛诊断。

### 2.2 原绘图方法的主要问题

旧图直接对全部样本做 40×40 二维直方图，并在未平滑的格点计数上画概率等高线。对于约 10^3 量级样本、八维后验的任意二维投影，许多格子的计数很低。相邻格子的随机计数波动会被等高线解释为独立小岛，因此视觉上非常破碎。

这不是简单的“样本数小于某个阈值”，也不能由“保存了 10000 步”排除。保存步数、等权样本数、不同取值数和有效独立样本量是不同概念。

### 2.3 区分绘图伪影与真实后验结构的证据

诊断中保持样本固定，只改变二维显示方法：

- 对 V 波段相同样本，原始格点等高线产生约 36 条碎片路径；加入 1 格 Gaussian 平滑后，主体轮廓减少为约 2 条连贯路径。
- 使用 2139 个独立二维 Gaussian 随机样本作为绘图对照时，未经平滑的 40×40 直方图同样出现碎片轮廓。

因此可以确认：原图中的相当一部分“小岛”是有限样本在细网格上的离散化伪影。这个结果不证明后验已经收敛，也不证明所有非椭圆结构都是假的；它只说明“图很碎”本身不能作为未收敛证据。

## 3. 新 corner 方法：改善显示，但不改变后验判断

最终实现遵循以下原则。

### 3.1 始终保留的量

- 使用全部 `posterior_sample1d.txt_N` 等权样本，包括重复样本。
- DRW 参数和两个响应成分始终从同一联合样本行读取。
- 一维分布使用原始样本的 15.85%、50%、84.15% 分位数。
- 一维直方图使用 25 格实线阶梯，不平滑。
- 每个二维面板保留全部原始散点。
- 坐标范围包含全部样本和长尾，不按中央区间裁切。
- 不用解析 Gaussian 代替真实后验。

### 3.2 仅用于二维显示的平滑

- 二维直方图默认每轴 40 格。
- 对二维格点计数使用标准差 1 格的 Gaussian 平滑。
- 每个参数方向的物理平滑带宽不超过该参数原始中央 68.3% 区间宽度的 1/4，防止长尾把平滑尺度拉大。
- 平滑后重新按概率质量计算 68.3% 和 95.4% 包含区域。
- 这些是二维概率质量等高线，不称为一维“1 sigma/2 sigma”。

二维平滑只改变密度的显示估计，不移动散点，不改变一维分位数，也不改变后续科学汇总表。

### 3.3 先验边界和有序区域

- 从保存的 `para_names_line.txt_N` 读取有效参数边界。
- DRW 参数中的 `[0,0]` 占位值不视为真实边界。
- 在真实硬边界处使用反射平滑；在仅由样本极值形成的显示边缘使用零延拓。
- 密度不泄漏到先验之外。
- 两个分量重新标记时，相应参数使用两个原生分量边界的并集，避免错误裁切。
- 对实际以质心排序的参数，二维密度限制在允许的有序三角区域；历史 Gamma center 不冒充有序质心。

### 3.4 不足以解析主体时不画等高线

以下情况只显示散点，不绘制密度和等高线：

- 保存的联合样本少于 100；
- 不同联合取值少于 100；
- 某参数恒定；
- 某参数中央 68.3% 区间在全范围 40 格网格上不足 3 格。

最后一项对 UVM2 的长尾尤其重要：图仍保留全部尾部，但不会在无法解析的狭窄主体上制造貌似精确的轮廓。这些条件是显示分辨率保护，不是拟合收敛验收标准。

## 4. Mrk817_a 的结果解释边界

新版图显著减少了由格点计数造成的碎片，但不会把所有后验强制画成圆或椭圆：

- V 等样本较多的波段，主体等高线明显更连贯。
- UVM2 仍保留真实的离散感和长尾；部分参数涉及的面板因主体在全范围网格上不可解析而只画散点。
- “图变得连贯”说明显示估计更稳定，不等于 MCMC/嵌套采样收敛已经被证明。
- “图仍不漂亮”也不能单独说明拟合失败，仍需结合有效样本量、重复运行、先验边界、参数退化和恢复实验判断。

## 6. 三路并行导致的 OOM 事故

### 6.1 事故过程

最初用以下模式对其余九源进行三路并行：

```bash
printf '%s\n' SOURCE... | xargs -P3 -I{} \
  /home/leonhard/miniforge3/envs/mica2/bin/python -B \
  main.py {} corner --stage mica_gaussian2_free
```

三个首批源为 Mrk142、Mrk335、F9_a。它们几乎同时开始导出第一个 M2 corner。随后 Codex/WSL 会话崩溃。

### 6.2 内核证据

上一轮 WSL 内核日志在 2026-09-22 17:39:55 明确记录：

- `python invoked oom-killer`；
- 三个绘图 Python 的常驻内存约为 1.9、2.0、2.0 GiB；
- WSL 可用内存几乎耗尽；
- 2 GiB swap 已全部使用；
- OOM killer 杀死 PID 10903 的 Python，`anon-rss` 约 2.03 GiB；
- WSL 在约 17:42 重新启动。

因此“绘图与崩溃同时发生”不是单纯时间相关：三路 PDF 导出确实直接触发了 WSL OOM。Codex 进程没有被内核直接选为牺牲进程，但内存枯竭和随后 WSL 重启足以解释用户看到的 GPT/Codex 崩溃。

### 6.3 损坏产物

崩溃时三个进程都正在写 M2 PDF。以下文件有文件名和非零大小，但 `pdfinfo` 无法读取，且末尾没有合法 PDF 结束结构：

- `Mrk142_M2_2comp_gaussian_corner.pdf`
- `Mrk335_M2_2comp_gaussian_corner.pdf`
- `F9_a_M2_2comp_gaussian_corner.pdf`

这三份损坏文件已按用户要求删除。修复后已经重新生成并通过完整性检查。

## 7. 内存根因：不是样本数组，而是 PDF 混合栅格渲染

八参数 corner 的画布边长为：

```python
side = 1.85 * ndim + 0.9
```

当 `ndim=8` 时，画布约为 15.7×15.7 英寸。原实现对每个二维面板的散点和 `pcolormesh` 都设置了 `rasterized=True`。项目样式的 `savefig.dpi` 为 300。Matplotlib PDF 的混合矢量/栅格后端会为多个栅格化面板建立大型临时画布；面板数量增加后，临时缓冲远大于样本数组本身。

格式分离实测进一步确认了根因：

| 导出方式 | 最大 RSS |
|---|---:|
| 原三路事故中的单个进程 | 约 1.9–2.0 GiB |
| 第一轮修复后，PDF+PNG | 1,897,472 KiB，约 1.81 GiB |
| 第一轮修复后，仅 PDF | 1,714,384 KiB，约 1.64 GiB |
| 第一轮修复后，仅 300 dpi PNG | 335,164 KiB，约 327 MiB |
| 最终修复后，仅全矢量 PDF | 163,816 KiB，约 160 MiB |
| 最终修复后，PDF+PNG | 348,660 KiB，约 341 MiB |

因此 300 dpi PNG 不是主要问题；真正的问题是 PDF 内的逐面板混合栅格化。

## 8. 修复过程及为何第一轮不够

### 8.1 第一轮修复

第一轮采取了：

- PDF 栅格层降为 180 dpi；
- 去掉 `bbox_inches="tight"`，避免额外的全画布 tight-bbox 渲染；
- 使用同目录临时文件，完整保存后再原子替换正式文件。

原子写入解决了“中断留下半写文件”的可靠性问题，但内存峰值仍为约 1.81 GiB。PDF-only 测试仍为约 1.64 GiB，说明降低栅格 DPI 并未消除混合后端的结构性开销。

### 8.2 最终修复

最终实现为：

1. PDF 中不再对散点和二维密度设置 `rasterized=True`，PDF 全部保持矢量；
2. PNG 仍以真实 300 dpi 导出；
3. 固定 GridSpec 已预留边距，因此不再使用 `bbox_inches="tight"`；
4. PDF 和 PNG 都先写入同目录临时文件，只有 `savefig` 成功返回后才用原子替换更新正式文件；
5. 任一导出失败时删除临时文件，保留原来的完整正式文件。

全矢量 PDF 的代价是文件可能比栅格层 PDF 稍大，但实测仍合理：

- Mrk142/M2：约 1.26 MB；
- Mrk335/M2：约 1.82 MB；
- F9_a/M2：约 2.19 MB。

PDF 的文字、轮廓、散点和密度均可无损缩放，科学内容没有变化。

## 10. 并行度的重新评估

事故前对内存的估计明显偏低。修复前必须以实测为准：三路约需 6 GiB，仅绘图就接近 WSL 6.6 GiB 上限，加上系统和 Codex 后必然危险。

最终修复后的单进程峰值约为 341 MiB，因此粗略估计：

| 并发数 | 绘图进程合计峰值估计 | 判断 |
|---:|---:|---|
| 2 | 约 0.7 GiB | 很安全 |
| 3 | 约 1.0 GiB | 安全 |
| 6 | 约 2.0 GiB | 当前 6.6 GiB WSL 下可接受 |

以上是基于已测 M2 波段的工程估计，不是内存硬保证。运行时还应避免同时启动 MICA 拟合、其他大型 Python 任务或大量 WSL 文件缓存。当前建议批量 corner 使用 `-P6`，若系统同时承担其他重任务则降为 `-P3` 或 `-P2`。

## 12. 本次可迁移的经验

### 科学判断

1. corner 图的碎片轮廓可能来自有限样本与细网格的组合，不能直接等同于未收敛。
2. 平滑应只作用于显示密度，并同时保留原始散点、原始分位数和完整尾部。
3. 对照应固定样本，只改变绘图方法；最好加入已知 Gaussian 样本作为绘图基准。
4. 分箱或轻度平滑后消失的小岛不能作为确定多峰证据。
5. 显示稳定性与采样收敛是两个验收层次，不能互相替代。

### 工程实现

1. “只是画图”也可能因高维多面板、高 DPI 和混合后端产生 GiB 级峰值。
2. 并行度必须由单进程实测 RSS 推导，不能只按样本数组大小估计。
3. OOM 后应检查上一轮 `journalctl -b -1 -k`；重启后的当前 `dmesg` 可能已经丢失关键证据。
4. 科研产物应原子写入，避免中断后留下看似存在但实际损坏的 PDF。
5. PDF 和 PNG 必须分格式测量；本次 PNG 很轻，PDF 混合栅格才是根因。
6. 批量绘制前先做单波段真实基准，再逐步增加并发，不应直接用全部源做压力测试。
